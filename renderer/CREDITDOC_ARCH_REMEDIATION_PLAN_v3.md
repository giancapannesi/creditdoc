## The founder's mandate

> "keep looping and saving through the stages all the way until we
> have removed the neccessity to rebuild the entire site every time."

Concretely: no more 10–15 minute full-site Astro rebuilds every time a
single lender row, comparison, or blog post changes. Content must be
addressable — write one row, re-render one page, ship one file.

## The three big rocks blocking "no more full rebuilds"

### Rock 1 — `_worker.js/` is still an Astro-adapter SSR shim (~5MB)

`@astrojs/cloudflare` emits `dist/_worker.js/` even in `output: 'static'`
mode when any page has `prerender = false` or when middleware is present.
Today CreditDoc has:

- 6 SSR routes (per `scripts/check_no_ssr_regression.mjs` allowlist):
  `/go/*`, `/r/*`, `/linkedin`, `/search/*`, `/affiliates/*`, `/sitemap.xml`
- 647-line middleware (`src/middleware.ts`) that runs on every static
  request too (CDN cache headers, referrer-cookie forwarding, geo header)

Astro's build bundles all of this into `_worker.js/`. Even prerendered
pages route through the worker for the middleware pass. **This is what
forces the full Astro build even for static pages.**

**Deliverable:** hand-rolled Cloudflare Worker in `worker/index.ts`
(TypeScript, ~150 LoC estimated) that:

1. Serves static files from `dist/` (Static Assets binding — already
   configured, currently unused because Astro adapter overrides it)
2. Handles the 6 dynamic routes inline (redirect table + LinkedIn OAuth
   callback + simple sitemap concat)
3. Adds the CDN cache headers + referrer forwarding + geo header (the
   critical bits from current middleware — most of the 647 lines are
   dead code from earlier iterations)
4. Deploys via `wrangler deploy --assets dist` — no Astro adapter

Then `astro.config.mjs`: `output: 'static'`, remove `@astrojs/cloudflare`,
remove `adapter`. Astro build produces plain HTML/JS/CSS. Wrangler ships
`dist/` as static + our worker for the 6 dynamic routes.

### Rock 2 — Static pages still emit Astro fingerprints

The ~482 remaining Astro-fingerprinted pages (credit-guide, best, tools,
research, resources, about, courses, legal) still carry:

- Fingerprinted `<script src="/_astro/hoisted.abc123.js">` tags
- Fingerprinted CSS bundle refs
- Astro island hydration shells
- Random SVG gradient IDs (best/[slug] specifically)

Each new Astro build changes the fingerprints → whole-site rebuild
needed to keep asset refs coherent → mandate violated.

**Deliverable:** either

- (**Path A — preferred**) Extend the renderer to cover the remaining
  482 pages. Estimated effort: 3 days.
  - `/credit-guide/` → 1 day (Supabase ETL + template port; deferred
    to Phase 3.3)
  - `/best/` → 0.5 day (Phase 3.8; use `random.seed(slug)` for SVG
    gradient IDs for deterministic output)
  - `/tools/`, `/research/`, `/resources/`, `/about/`, `/courses/` →
    1 day (Phase 3.9, mostly hand-authored static)
  - Legal pages → 0.5 day (Phase 3.10, purely static content pages)

- (**Path B — fallback**) Post-process Astro's output to strip
  fingerprints via `scripts/strip-astro-fingerprint.py` (already exists
  from Phase 0 POC, wired to package.json postbuild for /review/). Extend
  it to cover all remaining families. Loses the "no Astro rebuild ever"
  goal but achieves URL-stability.

Path A ships the mandate. Path B is a bridge if Path A slips.

### Rock 3 — Content-change → single-page re-render pipeline

Even with all pages renderer-covered, we need the plumbing to make a
single-row DB change → single-file dist write → single-file deploy.

Current state:

- `renderer/watch_and_rebuild.py` runs as cron (60s poll), reads
  `data/creditdoc.db` `updated_at`, re-renders any lender/answer/blog
  whose row is newer than the last render.
- Writes to `dist/<family>/<slug>/index.html` atomically.
- Does **NOT** deploy — still requires manual `wrangler deploy dist` or
  the deploy.sh helper.

**Deliverable:** extend `watch_and_rebuild.py` to also do a per-file
Cloudflare deploy via the Cloudflare API's `PUT
/accounts/{account_id}/workers/scripts/{name}/assets/{path}` endpoint
(Static Assets API). Batch the API calls at cron boundary (all changed
files in one PUT if possible). Skip if no changes.

If per-file deploy isn't supported (Cloudflare requires full assets
manifest push), fall back to incremental `wrangler deploy dist` on
change-detected cron ticks — still avoids the Astro rebuild step.

## Definition of "done" for the mandate

The mandate is met when **all three** are true:

1. `astro build` no longer runs on any content change (only on
   framework upgrades or when static-content files themselves change).
2. `dist/` contains no `_astro/` or `_worker.js/` directories after a
   clean renderer build.
3. `renderer/watch_and_rebuild.py` picks up a DB row change and
   deploys the corresponding single page to production in ≤90 seconds
   with no full-site rebuild.

Currently 0/3. This plan gets us to 3/3 in ~7 working days if Phase 3.3
Supabase ETL doesn't slip.

## What we deliberately don't do in v3

- No full CMS. Content lives in `data/creditdoc.db` + `data/*.json` +
  `src/content/*` — same as today. Renderer reads directly.
- No new build system. Jinja2 + Python + wrangler is the whole stack.
- No page-specific caching layer. Cloudflare edge already caches; the
  worker sets `Cache-Control` headers.
- No incremental static regeneration. That's a Next.js concept; our
  equivalent is `watch_and_rebuild.py` doing per-page atomic writes.
